# ADR 0002: send-to-kindle をRustに移植する

ステータス: 採択→0003、0005、0006、0008

## 文脈

[tett23/dotfiles の `bin/send-to-kindle`](https://github.com/tett23/dotfiles/blob/master/bin/send-to-kindle) は、ファイルをKindleのメールアドレスへ添付して送るDenoスクリプトである。
挙動はdotfilesのADR [0021](https://github.com/tett23/dotfiles/blob/master/docs/adr/0021-modernize-send-to-kindle.md)、[0022](https://github.com/tett23/dotfiles/blob/master/docs/adr/0022-send-to-kindle-env-file-option.md)、[0025](https://github.com/tett23/dotfiles/blob/master/docs/adr/0025-send-to-kindle-single-file.md)で決まっている。

- 使い方は `send-to-kindle [--env-file <パス>] <ファイル>`。
- 設定は `--env-file` で指定したファイル、無ければカレントディレクトリの `.env`、それも無ければ環境変数から読む。
- 件名「変換」、本文「book」でファイルを添付し、SMTPで送る。
- 失敗したらメッセージを表示して終了コード1で終わる。

実行にDenoとnpm・jsrのパッケージ取得が必要で、初回起動が遅く、実行環境にも依存する。
単一のネイティブバイナリにして、どこでも同じように使えるようにしたい。
このリポジトリをその移植先とする。

## 実装すること

### 構成

- リポジトリ直下をCargoパッケージ `send-to-kindle`（edition 2024、バイナリ1つ）とする。`tools/adr-guard` は独立したワークスペースのまま変えない。
- 純粋な処理と副作用を分ける。
  - `src/args.rs`：引数の解釈
  - `src/dotenv.rs`：`.env` の解析
  - `src/config.rs`：設定の読み込みと検証。`.env` の中身と環境変数を読む関数を引数で受け取る。
  - `src/mail.rs`：送るメールの組み立て（添付ファイルのContent-Typeの判定を含む）
  - `src/main.rs`：入出力だけを受け持つ（ファイルの読み込み、存在確認、送信、終了コード）
- インストールは `cargo install --path .` とする。

### 依存の方針

小さく再実装が容易なライブラリには依存せず、必要な範囲だけを再実装する。
次のすべてを満たすものを「小さく再実装が容易」とみなす。

- 必要な範囲が数十〜百数十行程度で書ける。
- 必要な仕様が小さく、変わりにくい。
- 正しさに暗号やプロトコルなどの専門的な知識を要さない。

この方針により、依存は検討の時点で次のように決めた。

- 依存する
  - `lettre`：SMTP送信とメール（MIME）の組み立て。SMTP、MIMEのエンコード、TLSは小さくない。同期APIを使い、非同期ランタイムは入れない。TLSには rustls を使う。
- 再実装する
  - 引数の解釈（`lexopt` や clap の代わり）。オプションは `--env-file` の1つだけで、エラー時の表示と終了コード（1）も移植元に合わせやすい。
  - `.env` の解析（`dotenvy` の代わり）。必要な書式は後述の範囲に限る。
  - 添付ファイルのContent-Typeの判定（`mime_guess` の代わり）。Kindleが受けつける形式の拡張子だけを対応づける。

### 再実装する部分の仕様

- 引数
  - `--env-file <パス>`、`--env-file=<パス>`、`-e <パス>` を解釈する。
  - `--` より後ろはすべてファイルとして扱う。`-` だけの引数もファイルとして扱う。
  - それ以外の `-` で始まる引数は知らないオプションとしてエラーにする。
- `.env`
  - 空行と、`#` で始まる行は無視する。
  - `KEY=VALUE` の形式とし、行頭の `export ` は無視する。キーと値の前後の空白は取り除く。`=` を含まない行は無視する。
  - 値がシングルクォートで囲まれていれば、中身をそのまま使う。
  - 値がダブルクォートで囲まれていれば、`\n`、`\r`、`\t`、`\"`、`\\` をエスケープとして解釈する。
  - クォートしない値では、空白に続く `#` 以降をコメントとして取り除く。
  - 変数展開（`${VAR}`）と、複数行にわたる値には対応しない。
  - 同じキーが複数あれば、後のものを使う。
- Content-Type
  - 拡張子（大文字小文字を区別しない）から次のように決める。それ以外は `application/octet-stream` とする。
    - `epub`：`application/epub+zip`
    - `pdf`：`application/pdf`
    - `doc`：`application/msword`
    - `docx`：`application/vnd.openxmlformats-officedocument.wordprocessingml.document`
    - `rtf`：`application/rtf`
    - `txt`：`text/plain`
    - `htm`、`html`：`text/html`
    - `jpg`、`jpeg`：`image/jpeg`
    - `gif`：`image/gif`
    - `png`：`image/png`
    - `bmp`：`image/bmp`

### 挙動（移植元と同じにする）

- 引数
  - `--env-file <パス>`、`--env-file=<パス>`、`-e <パス>` で設定ファイルを指定できる。オプションはファイルの前後どちらに置いてもよい。
  - ファイルがちょうど1つでなければ、使い方を表示してエラーにする。
  - 知らないオプションや、値の無い `--env-file` はエラーにし、理由と使い方を表示する。
- 設定
  - 必要な項目は `EMAIL`、`SEND_TO_KINDLE_EMAIL`、`SMTP_HOST`、`SMTP_PORT`、`SMTP_USER_NAME`、`SMTP_PASSWORD`。
  - `--env-file` を指定したときはそのファイルから読む。ファイルが無ければ `指定した .env がありません: <パス>` でエラーにする。
  - 指定しないときは、カレントディレクトリの `.env` があればそこから、無ければ環境変数から読む。
  - `.env` から読むときは、足りない項目を環境変数で補わない。
  - 空文字の項目は足りないものとして扱う。足りない項目は、読んだ場所とともに `<場所>に次の設定がありません: <項目, ...>` の形で列挙する。場所は「環境変数」、またはファイルのパスに空白を付けたもの。
  - `SMTP_PORT` は正の整数（先頭が0でない数字列）でなければ `SMTP_PORT は正の整数で指定してください: <値>` でエラーにする。
- メール
  - 送信元 `EMAIL`、送信先 `SEND_TO_KINDLE_EMAIL`、件名「変換」、本文「book」。
  - 添付ファイルの名前はパスのファイル名部分とする。相対パスはカレントディレクトリを基準に解決し、絶対パスはそのまま使う。
  - 添付するパスが通常のファイルでなければ `ファイルがありません: <解決後のパス>` でエラーにする。
- 送信
  - ポート465では最初からTLSで接続し、それ以外ではサーバーが対応していればSTARTTLSでTLSに切りかえる。移植元（nodemailerの既定）と同じ。
  - 認証には `SMTP_USER_NAME` と `SMTP_PASSWORD` を使う。
  - 失敗したら `送信できませんでした: <理由>` でエラーにする。
  - 成功したら標準出力に `送信しました: <ファイル名> → <送信先>` を表示する。
- エラーは標準エラー出力に `send-to-kindle: <メッセージ>` の形で表示し、終了コード1で終わる。

### ドキュメント

- 実装時に `docs/specifications.md` と `README.md` に、使い方・設定・挙動を記載する。
- 依存の方針は、このリポジトリ全体の方針として `docs/specifications.md` に記載する。

## 実装しないこと

- 移植元にない機能の追加（`--help`、`--version`、複数ファイルの一括送信、件名や本文の変更など）。
- dotfiles側の `bin/send-to-kindle` の削除や置きかえ。
- ビルド済みバイナリの配布やリリースの自動化。
- CIの設定。
- 外部のSMTPサーバーへ実際に送るテスト。

## テスト設計

`cargo test` で実行する。移植元のテスト（`Deno.test`）をすべて同じ内容で移す。

- 引数（`args.rs` の単体テスト）
  - ファイルだけを指定できる。
  - `--env-file <パス>`、`--env-file=<パス>`、`-e <パス>` で設定ファイルを指定できる。ファイルより後ろに置いてもよい。
  - ファイルが無い、またはファイルが2つ以上ならエラー（使い方を表示）。
  - `--env-file` の値が無い、または知らないオプションならエラー。
  - `--` より後ろの `-` で始まる引数と、`-` だけの引数はファイルとして扱う。
- `.env`（`dotenv.rs` の単体テスト）
  - 空行とコメント行を無視する。`=` を含まない行も無視する。
  - `export ` を無視し、キーと値の前後の空白を取り除く。
  - シングルクォートの中身はそのまま使い、ダブルクォートの中身はエスケープを解釈する。
  - クォートしない値の、空白に続く `#` 以降を取り除く。クォートした値の中の `#` は残す。
  - `${VAR}` は展開せず、文字列のまま使う。
  - 同じキーは後のものを使う。
- 設定（`config.rs` の単体テスト）
  - `.env` があれば `.env` の値を使い、環境変数は見ない。
  - `.env` が無ければ環境変数の値を使う。
  - 足りない項目を、読んだ場所とともに列挙してエラーにする。
  - 空文字の項目は足りないものとして扱う。
  - 指定したファイルから読んだときは、そのパスをエラーに出す。
  - `SMTP_PORT` が正の整数でなければエラー（`smtp`、`0`、`0587`、`-1` など）。
- メール（`mail.rs` の単体テスト）
  - 送信元・送信先・件名・本文と、ファイルの添付を組み立てる。
  - 絶対パスのファイルはカレントディレクトリと結合しない。
  - 拡張子からContent-Typeを決める。大文字の拡張子も判定し、未知の拡張子や拡張子の無いファイルは `application/octet-stream` にする。
- 結合テスト（ビルドしたバイナリを実行する）
  - 引数・設定・ファイルのエラーで終了コード1になり、標準エラー出力に `send-to-kindle: ` で始まるメッセージが出る。
  - テスト内で起動したローカルのSMTPサーバー（TLSなし）に送り、件名・送信元・送信先・本文・添付ファイル名・添付の中身が届くことを確かめる。日本語のファイル名を含める。

## トレードオフ

- 小さなライブラリを再実装すると、依存の更新やライセンスの確認が減り、ビルドも軽くなる。一方で、再実装した部分のテストと保守は自分たちで負う。必要な範囲を仕様として明記し、テストで固定することで補う。
- `.env` の解析を再実装し、対応する書式を絞るため、変数展開や複数行の値など、`@std/dotenv` が受けつける書式の一部は扱えない。通常の `KEY=VALUE` の形式では同じ結果になる。
- Content-Typeの判定をKindleが受けつける形式に絞るため、それ以外のファイルは `application/octet-stream` として送る。Kindleは対応していない形式を受けつけないため、実用上の影響はない。
- 知らないオプションなどのエラーメッセージの文面は、Node.jsの `parseArgs` と同じにはならない。終了コードと、使い方を表示することは合わせる。
- STARTTLSに対応していないサーバーには平文で認証情報を送る。移植元と同じ挙動を優先した。STARTTLSを必須にするかは別のADRで判断する。
- 移植元は1ファイルにまとめていた（dotfilesのADR [0025](https://github.com/tett23/dotfiles/blob/master/docs/adr/0025-send-to-kindle-single-file.md)）が、これはスクリプトを単体でコピーして使うためだった。Rustではバイナリを配るため、テストしやすさを優先してモジュールに分ける。
- `lettre` と rustls によって依存とビルド時間が増える。SMTP、MIME、TLSは小さく再実装が容易とはいえず、自前で書くより安全で保守しやすいため受け入れる。

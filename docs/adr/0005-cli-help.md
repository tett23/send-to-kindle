# ADR 0005: CLIのヘルプを追加する

ステータス: 採択

## 文脈

ADR 0002 では、移植元にない機能を追加しない方針から、`--help` を「実装しないこと」とした。
現在、使い方を知る手段は、引数を誤ったときに表示される1行の使い方（`使い方: send-to-kindle [--env-file <パス>] <ファイル>`）と、READMEや `docs/specifications.md` だけである。

このコマンドを使うには、6つの設定項目、設定を読む順序、件名「変換」の意味など、1行の使い方からはわからない知識が要る。
インストールしたバイナリだけで使い方がわかるよう、ヘルプを表示できるようにしたい。

## 実装すること

- `-h` または `--help` を指定したら、ヘルプを標準出力に表示し、終了コード0で終わる。
  - `--` より前にあれば、ほかの引数（不正なものを含む）にかかわらずヘルプを表示する。設定やファイルは読まない。
  - `--` より後ろの `-h`、`--help` は、これまでどおりファイルとして扱う。
- ヘルプには次の内容を、この順で載せる。
  1. コマンド名とバージョン（`Cargo.toml` の `version`）、1行の説明
  2. 使い方（エラー時に表示するものと同じ文字列）
  3. 引数：`<ファイル>` と、相対パスの解決
  4. オプション：`-e, --env-file <パス>` と `-h, --help`
  5. 設定：読む順序と、`.env` から読むときは環境変数で補わないこと。6つの設定項目とその意味。`SMTP_PORT` の範囲とTLSの扱い
  6. 送信内容：件名「変換」でKindleが形式を変換すること。Content-Typeを判定する拡張子
  7. 例：ファイルだけを指定する例と、`--env-file` を指定する例
- ヘルプの文面は `src/help.rs` に置く。設定項目の一覧は、`config.rs` の必要な項目の一覧と食い違わないようテストで確かめる。
- 引数の解釈の結果に「ヘルプの表示」を加える。
- `docs/specifications.md` と `README.md` に `--help` を記載する。
- ADR 0002 のステータスを `採択→0003、0005` にする。

## 実装しないこと

- `--version`。バージョンはヘルプの先頭に載せる。
- 引数の誤りのときに「詳しくは `--help`」と案内する1行の追加。エラーの文面を移植元と同じに保つ（ADR 0002）。
- 英語など、日本語以外のヘルプ。
- manページやシェル補完の生成。
- ヘルプのためのライブラリの導入。依存の方針（ADR 0002）に従い、文面は手で書く。

## テスト設計

- 引数（`args.rs` の単体テスト）
  - `-h`、`--help` だけを指定すると、ヘルプの表示になる。
  - ファイルや `--env-file` と一緒に指定しても、ヘルプの表示になる（`--help` が前でも後ろでも）。
  - 知らないオプションやファイルが2つ以上あっても、ヘルプの表示になる。
  - `--` より後ろの `--help` はファイルとして扱う。
- ヘルプ（`help.rs` の単体テスト）
  - 使い方の文字列（`USAGE`）と、`Cargo.toml` のバージョンを含む。
  - `config.rs` の必要な項目をすべて含む。
- 結合テスト
  - `--help` で終了コード0になり、標準出力にヘルプが出て、標準エラー出力には何も出ない。
  - 設定もファイルも無いディレクトリで実行しても、ヘルプが出る。

## トレードオフ

- 設定項目や拡張子の説明を、ヘルプ、`docs/specifications.md`、READMEの三か所に書くことになる。仕様の変更時に更新漏れが起きうる。設定項目の一覧だけはテストで突き合わせ、それ以外はADRで仕様を変えるときに三か所を更新する運用で補う。
- 不正な引数があってもヘルプを優先するため、`send-to-kindle --unknown --help` はエラーにならない。使い方を調べようとしている利用者にエラーを返すより親切だと判断した。
- ヘルプの文面を手で書くため、オプションを追加したときにヘルプへの追記を忘れうる。オプションは現在2つだけで、ライブラリを入れるほどではない。

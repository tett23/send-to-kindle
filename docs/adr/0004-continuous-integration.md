# ADR 0004: GitHub ActionsでCIを設定する

ステータス: 採択→0006

## 文脈

リポジトリをGitHubに公開した（tett23/send-to-kindle）。
現在、フォーマット・lint・テストは手元で実行しているだけで、実行し忘れたまま変更がpushされうる。

また、ADR 0001 ではコミット済みのADRの変更をpre-commit hookとClaude Codeのhookで防いでいる。
しかし、次の場合は防げない。いずれもADR 0001 の「実装しないこと」に挙げた穴である。

- `core.hooksPath` を設定していないクローンからのコミット
- `git commit --no-verify` によるコミット
- GitHubのWeb UIでの編集

push時とプルリクエスト時に、これらをCIで検査したい。

## 実装すること

### ワークフロー

- `.github/workflows/ci.yml` に1つのワークフローを置く。
- 起動条件は、`main` へのpushと、プルリクエストとする。
- `permissions` は `contents: read` だけにする。
- 同じブランチやプルリクエストで新しい実行が始まったら、古い実行は取り消す（`concurrency` の `cancel-in-progress`）。
- 実行環境は `ubuntu-latest` だけとする。

### ジョブ

- `rust`：リポジトリ直下（`send-to-kindle`）と `tools/adr-guard` のそれぞれで、次を実行する。
  - `cargo fmt --check`
  - `cargo clippy --all-targets -- -D warnings`
  - `cargo test`
- `adr`：対象範囲のコミットについて、コミット済みのADRが変更されていないことを検査する（後述）。

### ツールチェインとキャッシュ

- ランナーにあらかじめ入っている `rustup` で、stableのツールチェインに `rustfmt` と `clippy` を入れる。サードパーティのアクションは使わない。
- 使うアクションは `actions/checkout` と `actions/cache` だけとし、コミットのSHAで固定する（タグはコメントで併記する）。
- `actions/cache` で `~/.cargo/registry`、`~/.cargo/git`、各クレートの `target` をキャッシュする。キーには `Cargo.lock` のハッシュを含める。

### コミット済みADRの検査

- `adr-guard` に、コミットの範囲を検査するサブコマンド `adr-guard check-range <base> <head>` を追加する。
  - `<base>..<head>` に含まれるマージ以外の各コミットについて、親コミットとの差分を、pre-commit hookと同じ規則で検査する。
    - 親コミットに存在する `docs/adr/` 以下のファイルの、ステータスの行以外の変更、削除、リネームを違反とする。
    - 新規追加は許可する。
  - 違反したコミットとファイルをすべて表示し、1件でもあれば終了コード1で終わる。
  - pre-commit hookと判定の処理を共有する。
- CIでの範囲は次のとおりとする。
  - プルリクエスト：ベースブランチの先端からプルリクエストの先端まで
  - `main` へのpush：push前の先端（`github.event.before`）からpush後の先端まで。push前の先端が無い場合（ブランチの新規作成など）は、ルートコミットから検査する。
- 範囲内の全コミットを読むため、チェックアウトでは全履歴を取得する（`fetch-depth: 0`）。
- ADR 0001 のステータスを `採択→0004` にする。

### ドキュメント

- `docs/specifications.md` の開発プロセスに、CIで検査する内容を記載する。
- `README.md` にCIのバッジを付ける。

## 実装しないこと

- macOSやWindowsでのテスト。
- MSRV（対応する最小のRustのバージョン）の検査。
- `main` ブランチの保護ルール（必須チェックの設定）。GitHubのリポジトリ設定であり、ワークフローの外で手で行う。
- リリースの自動化、バイナリの配布。
- 依存の脆弱性検査（`cargo audit` など）や、依存の自動更新（Dependabotなど）。
- Claude CodeのPreToolUse hookの変更。

## テスト設計

- `adr-guard check-range`（`tools/adr-guard` の結合テスト。一時ディレクトリにgitリポジトリを作る）
  - ADRを追加するだけのコミットの範囲は成功する。
  - コミット済みADRのステータス行だけを変えるコミットの範囲は成功する。
  - 範囲内のどれか1つのコミットがコミット済みADRの本文を変えていれば失敗する。後のコミットで元に戻していても失敗する。
  - 範囲内のコミットでコミット済みADRを削除・リネームしていれば失敗する。
  - 範囲内で追加したADRを、同じ範囲内の後のコミットで書きかえていれば失敗する。
  - 範囲外（`<base>` 以前）のコミットは検査しない。
  - マージコミットは検査しない。
- pre-commit hookの既存の結合テストがすべて通ること（判定の処理を共有するため）。
- ワークフロー
  - このADRを実装したプルリクエストで、全ジョブが成功することを確かめる。
  - 同じプルリクエストで一時的にフォーマット違反を入れ、`rust` ジョブが失敗することを確かめてから戻す。

## トレードオフ

- 実行環境をUbuntuだけにすると、macOSでだけ起きる不具合（パスの扱いなど）はCIで見つからない。普段の開発はmacOSで行い、手元でテストするため、CIの時間を優先した。
- ツールチェインをstableにするため、Rustの新しいリリースで新しいclippyの警告が出てCIが失敗することがある。バージョンを固定すると、更新の手間がかかる。警告にはその時点で対応する。
- ADRの検査を差分全体ではなくコミットごとに行うため、プルリクエストの途中で一度でもADRを書きかえると、後で戻しても失敗する。「一度コミットしたADRは変更不可」という規則に合わせた。履歴を書きかえて（rebaseなどで）直す必要がある。
- サードパーティのアクション（`dtolnay/rust-toolchain` や `Swatinem/rust-cache` など）を使えばワークフローは短くなる。依存を増やさない方針（ADR 0002）に合わせ、ランナーに入っている `rustup` と公式のアクションで済ませた。

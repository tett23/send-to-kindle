# ADR 0008: 設定を項目ごとに重ねて読み、~/.config/send-to-kindle/.env を既定で読む

ステータス: 採択

## 文脈

ADR 0002 で、設定は次の順に探し、最初に見つかった1か所だけから読むと定めた（移植元と同じ）。

1. `--env-file` で指定したファイル
2. カレントディレクトリの `.env`
3. 環境変数

`.env` から読むときは、足りない項目を環境変数で補わない。

READMEでは、設定を `~/.config/send-to-kindle/.env` に置き、`--env-file` で指定する使い方を案内している。
しかし、送るたびに `--env-file ~/.config/send-to-kindle/.env` を付けるのは手間である。
また、設定を1か所からしか読まないため、パスワードだけを環境変数で渡す、送信先だけをディレクトリごとに変える、といった使い方ができない。

設定の置き場所を既定で決め、さらに項目ごとに上書きできるようにしたい。

## 実装すること

### 読む場所と優先順位

- 次の場所を、この優先順位で読む（上ほど優先する）。
  1. `--env-file` で指定したファイル
  2. 環境変数（シェルで指定されたもの）
  3. カレントディレクトリの `.env`
  4. ユーザーの設定ファイル
- 設定項目ごとに、優先順位の高い場所から順に探し、最初に見つかった値を使う。場所ごとに一部の項目だけを書いてよい。
  - 例：ユーザーの設定ファイルにすべての項目を書き、`SMTP_PASSWORD` だけを環境変数で上書きする。
- 空文字の値は、その場所に無いものとして扱い、次の場所を探す。
- `--env-file` で指定したファイルが無ければ、これまでどおり `指定した .env がありません: <パス>` でエラーにする。
- カレントディレクトリの `.env` とユーザーの設定ファイルは、無ければ読まない（エラーにしない）。存在するが読めない場合（権限が無いなど）はエラーにする。

### ユーザーの設定ファイルのパス

- 環境変数 `XDG_CONFIG_HOME` が絶対パスなら `$XDG_CONFIG_HOME/send-to-kindle/.env`
- そうでなければ `$HOME/.config/send-to-kindle/.env`
- `XDG_CONFIG_HOME` が空、または相対パスなら、設定されていないものとして扱う（XDG Base Directory仕様に従う）。
- `HOME` も設定されていなければ、ユーザーの設定ファイルは読まない。
- macOSでも `~/Library/Application Support` ではなく、上のパスとする。
- `XDG_CONFIG_HOME` と `HOME` は、シェルの環境変数から読む（`.env` の中の値は使わない）。

### エラーメッセージ

- 足りない項目のエラーは、次の形に変える。読んだ場所は、優先順位の順に、実際に読んだファイルと「環境変数」を並べる。

  ```
  次の設定がありません: SMTP_HOST, SMTP_PASSWORD（読んだ場所: 環境変数, .env, /Users/me/.config/send-to-kindle/.env）
  ```

- `SMTP_PORT` の値のエラー（ADR 0002、0003）の文面は変えない。

### 構成

- 各場所から読んだ値を、優先順位の順に並べて `config.rs` に渡し、項目ごとに解決する。`config.rs` はファイルや環境変数を直接読まない純粋な処理のままとする。
- ユーザーの設定ファイルのパスを決める処理は、環境変数を読む関数を引数で受け取る純粋な関数とし、単体テストする。

### ドキュメント

- ヘルプ（ADR 0005）の「設定」の説明を、読む場所・優先順位・項目ごとに重ねることに合わせて更新する。
- `docs/specifications.md` と `README.md` を更新する。READMEの設定の手順は、`.env.example` を `~/.config/send-to-kindle/.env` にコピーすれば `--env-file` なしで使える形にする。`.env.example` の冒頭のコメントも同様に更新する。
- ADR 0002 のステータスを `採択→0003、0005、0006、0008` にする。

## 実装しないこと

- ユーザーの設定ファイルの自動作成や、対話的な設定コマンド。
- `/etc` などシステム全体の設定ファイル。
- Windowsでの設定ファイルの場所（`%APPDATA%` など）。配布するバイナリにWindows向けは無い（ADR 0006）。
- 特定の場所を読まないようにするオプション。
- 設定項目の名前の変更（`SEND_TO_KINDLE_` などの接頭辞を付けること）。
- 設定ファイルの権限（ほかのユーザーから読めるかなど）の検査。
- どの値をどの場所から読んだかを表示する機能。

## テスト設計

- 設定の解決（`config.rs` の単体テスト）
  - 項目ごとに、優先順位の高い場所の値を使う（`--env-file` ＞ 環境変数 ＞ `.env` ＞ ユーザーの設定ファイル）。
  - 場所ごとに一部の項目だけがあれば、項目ごとに別の場所から集めて設定になる。
  - 空文字の値は無いものとして、次の場所の値を使う。
  - どの場所にも無い項目は、読んだ場所を優先順位の順に並べたエラーになる。
  - `SMTP_PORT` の検証（ADR 0002、0003）は、解決したあとの値に対してこれまでどおり行う。
- ユーザーの設定ファイルのパス（単体テスト）
  - `XDG_CONFIG_HOME` が絶対パスなら `$XDG_CONFIG_HOME/send-to-kindle/.env` になる。
  - `XDG_CONFIG_HOME` が無い、空、または相対パスなら `$HOME/.config/send-to-kindle/.env` になる。
  - `XDG_CONFIG_HOME` も `HOME` も使えなければ、パスは無い。
- 結合テスト（環境変数を空にし、`HOME` と `XDG_CONFIG_HOME` を一時ディレクトリに向けて実行する）
  - `$HOME/.config/send-to-kindle/.env` だけがあれば、そこから読んで送信できる。
  - `XDG_CONFIG_HOME` を設定すると、`$HOME/.config` ではなくそちらから読む。
  - ユーザーの設定ファイルにすべての項目があり、カレントディレクトリの `.env` に `SEND_TO_KINDLE_EMAIL` だけがあれば、送信先はカレントディレクトリの `.env` の値になる。
  - 環境変数の値は、カレントディレクトリの `.env` とユーザーの設定ファイルの値より優先される。
  - `--env-file` の値は、環境変数の値より優先される。
  - 足りない項目のエラーに、読んだ場所が優先順位の順に出る。
- ヘルプに、ユーザーの設定ファイルのパスと優先順位が含まれる。
- 既存のテストのうち、ADR 0002 の「最初に見つかった1か所だけから読む」挙動とエラーの文面を前提にしたものは、この仕様に合わせて書きかえる。

## トレードオフ

- 移植元と設定の読み方が変わる。これまでは `.env` があれば環境変数を見なかったが、今後は環境変数が `.env` より優先される。`.env` を使いながら、同じ名前の環境変数を別の用途で設定していると、意図しない値が使われる。
  - 特に `EMAIL` は、ほかのツール（gitやDebianの開発ツールなど）が使う一般的な名前で、シェルに設定されていることがある。その場合、`.env` やユーザーの設定ファイルの `EMAIL` より優先される。`--env-file` で指定すれば、環境変数より優先させられる。
  - 設定項目に接頭辞を付けて衝突を避ける変更は、既存の設定ファイルとの互換性を失うため、このADRでは行わない。
- 値が複数の場所から集まるため、どの値がどこから来たのかがわかりにくくなる。足りない項目のエラーには読んだ場所を並べて補う。
- `--env-file` を環境変数より優先するため、「環境変数で一時的に上書きする」使い方は、`--env-file` を指定したときには効かない。明示的に指定したファイルを最も信頼できる指定とみなした。
- macOSの慣習（`~/Library/Application Support`）に従わず `~/.config` を使う。CLIツールでは `~/.config` が広く使われており、READMEで案内してきた場所とも一致する。

# ADR 0003: SMTP_PORT の範囲を設定の読み込み時に検証する

ステータス: 採択

## 文脈

ADR 0002 では、`SMTP_PORT` が正の整数（先頭が0でない数字列）でなければエラーにすると定めた。
これは移植元の検証をそのまま移したもので、上限は定めていない。

一方、ポート番号は1〜65535の範囲であり、SMTPの送信には16ビットの値として渡す必要がある。
そのため、現在の実装では `65536` のような範囲外の値も設定の検証を通り、送信時に `送信できませんでした: ポート番号として使えません: 65536` というエラーになる。

この挙動には次の問題がある。

- 設定の誤りなのに「送信できませんでした」と表示されるため、送信先やネットワークの問題と紛らわしい。
- 設定の検証が設定の読み込みと送信の二か所に分かれている。

## 実装すること

- `SMTP_PORT` の検証を、設定の読み込み時に次の順で行う。
  1. 正の整数（先頭が0でない数字列）でなければ、ADR 0002 のとおり `SMTP_PORT は正の整数で指定してください: <値>` でエラーにする。
  2. 65535より大きければ `SMTP_PORT は 65535 以下で指定してください: <値>` でエラーにする。桁数が多く整数型に収まらない値も、これに含める。
- 設定の `SMTP_PORT` は、検証済みのポート番号（16ビットの符号なし整数）として保持する。
- 送信時のポート番号の検証（`ポート番号として使えません`）を削除する。
- `docs/specifications.md` の `SMTP_PORT` の記述を更新する。
- ADR 0002 のステータスを `採択→0003` にする。

## 実装しないこと

- 正の整数でない場合のエラーメッセージの変更。移植元と同じ文面を保つ。
- 0や先頭が0の値の扱いの変更。ADR 0002 のとおりエラーにする。
- よく使われるポート（25、465、587など）以外への警告。
- 他の設定項目（メールアドレスの形式など）の検証の追加。

## テスト設計

- 設定（`config.rs` の単体テスト）
  - `1` と `65535` は受けつけ、ポート番号として保持する。
  - `65536` と、整数型に収まらない桁数の値（例：`99999999999999999999`）は `SMTP_PORT は 65535 以下で指定してください: <値>` でエラーにする。
  - `smtp`、`0`、`0587`、`-1`、`+587`、`5 87` は、これまでどおり `SMTP_PORT は正の整数で指定してください: <値>` でエラーにする。
- 結合テスト
  - 送信時のポート番号エラーのテスト（`fails_when_port_is_out_of_range`）を、設定のエラーとして終了コード1と `SMTP_PORT は 65535 以下で指定してください: 65536` が出ることを確かめるテストに置きかえる。

## トレードオフ

- 範囲外の場合に専用のメッセージを出すため、エラーの文面が二種類になる。正の整数でない場合と同じ文面にすると、`65536` に「正の整数で指定してください」と表示され、誤りの理由が伝わらない。
- 全体を「1 から 65535 の整数で指定してください」にまとめる案もあるが、正の整数でない場合の文面が移植元と変わるため採らなかった。

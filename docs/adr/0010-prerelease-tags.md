# ADR 0010: `-` を含むタグはプレリリースとして作成する

ステータス: 採択

## 文脈

ADR 0006 で、`v` で始まるタグのpushでGitHubのリリースを作成するようにした。
タグが `v<Cargo.toml の version>` と一致すればリリースを作り、すべて通常のリリースとして公開している。

リリース前の確認のため、`v0.3.0-rc` のようなタグを使いたい。
このようなタグは、利用者がインストールする対象（最新のリリース）にならないよう、プレリリースとして扱う必要がある。

## 実装すること

- タグに `-` が含まれていれば（例：`v0.3.0-rc`、`v0.3.0-rc.1`）、リリースをプレリリースとして作成する（`gh release create --prerelease`）。
- `-` を含まないタグは、これまでどおり通常のリリースとして作成する。
- タグとバージョンの照合は変えない。プレリリースのタグを使うときは、`Cargo.toml` の `version` も同じ形（例：`0.3.0-rc`）にする。
- `docs/specifications.md` と `README.md` のリリースの手順に、プレリリースの扱いを記載する。
- ADR 0006 のステータスを `採択→0007、0010` にする。

## 実装しないこと

- プレリリースのタグの形式の検証（`-rc` 以外の `-alpha`、`-beta` なども、`-` を含めばプレリリースとする）。
- プレリリースのアーカイブの中身やターゲットの変更。
- プレリリースから通常のリリースへの昇格の自動化。通常のリリースは、別のタグ（例：`v0.3.0`）をpushして作る。

## テスト設計

- リリースの判定はワークフローのシェルで行う。次を実際のタグで確かめる。
  - `-` を含むタグをpushすると、プレリリースとして作成される（`gh release view <タグ> --json isPrerelease` が `true`）。
  - `-` を含まないタグは、これまでどおり通常のリリースとして作成される。次の通常のリリースで確かめる。
- 判定のシェルの断片を、手元で `-` を含むタグと含まないタグの両方について実行し、`--prerelease` の有無を確かめる。

## トレードオフ

- `-` の有無だけで判定するため、意図せず `-` を含むタグを作るとプレリリースになる。SemVerのプレリリースの表記と一致するため、規則として分かりやすさを優先した。
- プレリリースを確かめるたびに `Cargo.toml` の `version` を変えるコミットが要る。タグとバージョンの照合（ADR 0006）を保つため受け入れる。

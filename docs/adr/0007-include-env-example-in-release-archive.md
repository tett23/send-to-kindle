# ADR 0007: リリースのアーカイブに .env.example を含める

ステータス: 採択

## 文脈

ADR 0006 で、リリースのアーカイブの中身をバイナリ `send-to-kindle`、`LICENSE`、`README.md` と定めた。
その後、設定の例として `.env.example` をリポジトリに追加し、READMEでは `.env.example` をコピーして値を書きかえる手順を案内している。

しかし、リリースからインストールした利用者の手元には `.env.example` が無い。
READMEの手順をそのまま実行できず、設定項目を `--help` やREADMEから手で書き起こす必要がある。

## 実装すること

- リリースのアーカイブ（`send-to-kindle-<タグ>-<ターゲット>.tar.gz`）に `.env.example` を加える。中身はバイナリ `send-to-kindle`、`LICENSE`、`README.md`、`.env.example` とする。
- `.github/workflows/release.yml` の `Package` ステップで、`.env.example` をアーカイブのディレクトリにコピーする。
- アーカイブを作ったあと、上の4つのファイルがそろっていることを確かめ、欠けていればジョブを失敗させる。
- READMEの「展開して配置する」手順に、展開したディレクトリの `.env.example` を設定ファイルの置き場所へコピーする手順を加える。
- `docs/specifications.md` のリリースの成果物の記述を更新する。
- ADR 0006 のステータスを `採択→0007` にする。

## 実装しないこと

- 設定ファイルの置き場所（`~/.config/send-to-kindle/.env` など）を既定値として読む機能。設定を読む順序は変えない。
- インストール用のスクリプトの提供。
- `.env.example` 以外のファイル（ADRや `docs/specifications.md` など）のアーカイブへの追加。
- 既存のリリース（v0.1.0）のアーカイブの作り直し。次のリリースから反映する。

## テスト設計

- アーカイブの中身の確認はワークフローのシェルで行い、Rustのテストにはしない。
  - `Package` ステップで、アーカイブを `tar -tzf` で一覧し、4つのファイルがすべて含まれることを確かめる。欠けていれば失敗する。
- 次のリリースのタグをpushしたときに、次を確かめる。
  - 3つのアーカイブすべてに `.env.example` が含まれる。
  - 展開した `.env.example` を `--env-file` に指定すると、設定の検証を通る（ファイルが無いことによるエラーまで進む）。

## トレードオフ

- `.env.example` の内容がリポジトリとアーカイブの両方で配られるため、設定項目を変えたときにアーカイブ側は次のリリースまで古いままになる。設定項目の変更はADRとリリースを伴うため、実害は小さい。
- 中身の確認をワークフローに入れると、ステップが少し長くなる。ファイルの追加漏れでリリースが壊れることを防げるため、受け入れる。
- 実際のリリースでしか確かめられない部分が残る。確認のためだけにタグを打つことはせず、次のリリースで確かめる。

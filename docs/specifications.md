# 仕様

## send-to-kindle

ファイルをKindleのメールアドレスへ添付して送るコマンド（ADR 0002）。

### 使い方

```
send-to-kindle [--env-file <パス>] <ファイル>
```

- `--env-file <パス>`、`--env-file=<パス>`、`-e <パス>` で設定を読むファイルを指定する。オプションはファイルの前後どちらに置いてもよい。
- `--` より後ろの引数と、`-` だけの引数はファイルとして扱う。
- ファイルがちょうど1つでなければ、使い方を表示してエラーにする。
- 知らないオプションや、値の無い `--env-file` はエラーにし、理由と使い方を表示する。

### 設定

| 項目 | 内容 |
|---|---|
| `EMAIL` | 送信元のメールアドレス（Kindleの承認済みアドレス） |
| `SEND_TO_KINDLE_EMAIL` | Kindleのメールアドレス |
| `SMTP_HOST` | SMTPサーバーのホスト |
| `SMTP_PORT` | SMTPサーバーのポート |
| `SMTP_USER_NAME` | SMTPの認証に使うユーザー名 |
| `SMTP_PASSWORD` | SMTPの認証に使うパスワード |

- 次の順に、最初に見つかったところから読む。
  1. `--env-file` で指定したファイル。ファイルが無ければ `指定した .env がありません: <パス>` でエラーにする。
  2. カレントディレクトリの `.env`
  3. 環境変数
- `.env` から読むときは、足りない項目を環境変数で補わない。
- 空文字の項目は足りないものとして扱う。足りない項目は `<場所>に次の設定がありません: <項目, ...>` の形で列挙する。場所は「環境変数」、またはファイルのパスに空白を付けたもの。
- `SMTP_PORT` は正の整数（先頭が0でない数字列）でなければ `SMTP_PORT は正の整数で指定してください: <値>` でエラーにする。65535より大きければ `SMTP_PORT は 65535 以下で指定してください: <値>` でエラーにする（ADR 0003）。

### `.env` の書式

- 空行と、`#` で始まる行は無視する。`=` を含まない行も無視する。
- `KEY=VALUE` の形式とし、行頭の `export ` は無視する。キーと値の前後の空白は取り除く。
- 値がシングルクォートで囲まれていれば、中身をそのまま使う。
- 値がダブルクォートで囲まれていれば、`\n`、`\r`、`\t`、`\"`、`\\` をエスケープとして解釈する。
- クォートしない値では、空白に続く `#` 以降をコメントとして取り除く。
- 変数展開（`${VAR}`）と、複数行にわたる値には対応しない。
- 同じキーが複数あれば、後のものを使う。

### メール

- 送信元 `EMAIL`、送信先 `SEND_TO_KINDLE_EMAIL`、件名「変換」、本文「book」。件名が「変換」だと、Kindleは送ったファイルをKindleの形式に変換する。
- ファイルを1つ添付する。名前はパスのファイル名部分とする。相対パスはカレントディレクトリを基準に解決し、絶対パスはそのまま使う。
- 添付するパスが通常のファイルでなければ `ファイルがありません: <解決後のパス>` でエラーにする。
- 添付ファイルのContent-Typeは拡張子（大文字小文字を区別しない）から決める。それ以外は `application/octet-stream` とする。

  | 拡張子 | Content-Type |
  |---|---|
  | `epub` | `application/epub+zip` |
  | `pdf` | `application/pdf` |
  | `doc` | `application/msword` |
  | `docx` | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` |
  | `rtf` | `application/rtf` |
  | `txt` | `text/plain` |
  | `htm`、`html` | `text/html` |
  | `jpg`、`jpeg` | `image/jpeg` |
  | `gif` | `image/gif` |
  | `png` | `image/png` |
  | `bmp` | `image/bmp` |

### 送信

- ポート465では最初からTLSで接続し、それ以外ではサーバーが対応していればSTARTTLSでTLSに切りかえる。STARTTLSに対応していないサーバーには平文で送る。
- 認証には `SMTP_USER_NAME` と `SMTP_PASSWORD` を使う。
- 失敗したら `送信できませんでした: <理由>` でエラーにする。
- 成功したら標準出力に `送信しました: <ファイル名> → <送信先>` を表示する。

### エラー

- 標準エラー出力に `send-to-kindle: <メッセージ>` の形で表示し、終了コード1で終わる。

## 開発プロセス

### ADR

- 実装の前に `docs/adr/` にADRを作成し、人間のレビューを経てからコミットする。
- ファイル名は `0001-feature-details.md` の形式（4桁の連番＋kebab-case）とする。
- コミット済みのADRはステータスの行を除いて変更できない。仕様を変更する場合は新しいADRを作成する。
- この制約は次の二つのhookで強制する。検査はRust製の `tools/adr-guard` が担う（ADR 0001）。
  - gitのpre-commit hook（`.githooks/pre-commit`）
  - Claude CodeのPreToolUse hook（`.claude/settings.json`）

### 依存の方針

- 小さく再実装が容易なライブラリには依存せず、必要な範囲だけを再実装する（ADR 0002）。
- 次のすべてを満たすものを「小さく再実装が容易」とみなす。
  - 必要な範囲が数十〜百数十行程度で書ける。
  - 必要な仕様が小さく、変わりにくい。
  - 正しさに暗号やプロトコルなどの専門的な知識を要さない。
- 現在の依存は `lettre`（SMTP送信、MIME、TLS）だけである。引数の解釈、`.env` の解析、Content-Typeの判定は再実装している。
